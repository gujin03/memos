# 批量修改标签使用说明

> 一句话：**不改一行 memos 源码**，用「官方导出 → Python 脚本批量替换 → 官方导入」完成标签的批量重命名。这是目前发现的最轻、最稳、最高效的方案。

## 一、背景与思路

关于批量修改标签，之前让 AI 通读 memos 源码做过调研：**官方并没有计划增加这个功能**——作者甚至把几个相关 PR 主动关闭了。也就是说，这个特性在作者看来短期内不会纳入主线。

想自己实现，传统做法只有一条路：fork 源码，在后端和前端各打一个「批量改标签」的个性化补丁。问题是补丁要跟着上游版本反复重新维护，每次升级都可能冲突，长期成本很高。

昨天经过最新研究，发现了一个被忽略的突破口：**平台其实自带了导出和导入功能**（设置 → 导出和导入）。导出的 ZIP 文件中，每条备忘录分别对应一个 Markdown 文件和一条 JSON 记录；导入时备忘录会保留原有标识符（uid），重复导入同一文件**不会产生重复的备忘录**。

于是流程变成：**导出数据 → Python 脚本对 `.md` 和 `.json` 批量替换 → 再导入回去**。完全不用碰源码，官方怎么升级都不受影响。

| 路线 | 做法 | 代价与风险 | 结论 |
|---|---|---|---|
| 源码补丁 | fork memos，改后端＋前端新增批量改标签功能 | 需持续跟进上游，每次升级都可能冲突，维护成本高 | 不推荐 |
| 导出→替换→导入 | 官方导出 ZIP → `rename_tag.py` 批量替换 → 官方导入回原实例 | 零源码改动，升级无感，十分钟搞定 | **✅ 推荐（当前最高效）** |

## 二、原理：标签同时存在于两处，必须一起改

导出解压后，每条 memo 是一对文件：

- `<uid>.md` —— 备忘录正文，标签以 `#标签名` 的形式写在正文里；
- `<uid>.json` —— 备忘录元数据，标签保存在 `tags` 数组里，例如 `"tags":["bak","hw"]`。

**只改其中一处，导入后就会出现正文与标签栏不一致**。`rename_tag.py` 会把两处一起替换，保证一致性。

## 三、操作步骤

### 第 0 步：备份（强制，不可跳过）

脚本会**原地覆盖**文件、不带备份。动手前先把解压目录完整复制一份：

```bash
cp -r ~/Downloads/memos-export ~/Downloads/memos-export.bak
```

稳妥起见，建议同时对 memos 数据库也做一次备份（双保险）。

### 第 1 步：导出

memos 设置 → **导出和导入** → 下载文件（导出），得到 ZIP；解压到一个目录，里面是 `<uid>.json` + `<uid>.md` 成对出现。

### 第 2 步：把脚本放进导出目录

```bash
cp rename_tag.py /path/to/memos-export/
cd /path/to/memos-export
```

> ⚠️ 脚本只扫描**脚本所在目录**下的 `*.json`，所以必须和导出文件放在同一层。

### 第 3 步：先 dry-run 预览（强制）

```bash
python3 rename_tag.py 旧标签 新标签 --dry-run
```

确认输出里 `Found N memo(s)` 的数量、逐条列出的文件与标签是否符合预期。**这一步不做任何修改。**

### 第 4 步：正式替换

```bash
python3 rename_tag.py 旧标签 新标签
```

输出会逐条打印 `[json] tags: [...] -> [...]` 与 `[md] N replacement(s)`，最后汇总 `Renamed #旧标签 -> #新标签 in N pair(s)`。

### 第 5 步：重新打包导入

把改完的目录重新压缩成 ZIP（保持原有结构），回到 memos 设置 → **导出和导入** → 选择文件（导入）。

导入按 uid 覆盖更新，不会产生重复——memos 官方说明与实测结果一致。打包前记得把 `rename_tag.py` 从目录里移出去（不打包进去）。

### 第 6 步：验证

随机打开几条原本带旧标签的备忘录：正文里的 `#新标签`、标签栏的 `#新标签` 应都已更新。

## 四、脚本行为说明

命令格式：

```bash
python rename_tag.py <old_tag> <new_tag> [--dry-run]
```

- 标签参数**不带 `#`**（脚本会自动去掉）；
- **整词匹配**：`#bak` 不会误伤 `#backup`、`#bak2`；
- 正文与 JSON **同时替换**；若某条 memo 的 `.md` 缺失，则只改 JSON；
- 支持中文标签（UTF-8 原样输出）；
- 匹配**区分大小写**；
- 一次只处理一对标签，多个标签需逐对执行；
- 仅依赖 Python 3 标准库，无需安装任何第三方包。

## 五、风险与注意事项

1. **脚本原地覆盖、无备份** —— 第 0 步的目录备份不可省略；
2. **先 dry-run 再真跑** —— 看清 `Found N memo(s)` 再动手；
3. 多个标签批量修改 → 逐对执行，每对执行完看输出确认数量；
4. 导入虽按 uid 覆盖、不产生重复，但导入前仍建议备份数据库，防止误操作有回退余地；
5. 别把 `rename_tag.py` 一起打进导入的 ZIP（无害但没必要）。

## 六、常见问题

- **输出 `No memos found with tag '#xxx'`** → 检查标签拼写与大小写；确认脚本已放进导出目录（与 `.json` 同层）。
- **某条 memo 只有 JSON 变了、`.md` 没动** → 该 memo 正文里没有写过 `#标签`，标签只存在于元数据里，属正常现象。
- **想一次改多个标签** → 原版脚本一次一对，多执行几遍即可。
